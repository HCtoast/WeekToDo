# 주간 타임블록 TODO 위젯

서브모니터에 상주하는 Electron 데스크톱 위젯. **요일 컬럼 × 시간축** 그리드에 로컬 일정과
TODO, Google Calendar 일정을 함께 띄운다. 반투명 유리 배경으로 항상 위에 떠 있고,
한 줄로 말하면 알아서 일정을 만들어 준다.

Windows 전용이다 (유리 배경과 시작프로그램 등록이 Windows API에 기대고 있다).

## 왜 만들었나

캘린더 앱은 "몇 시에 무엇"은 잘 보여주지만 **"오늘 저녁 몇 시부터 시작해서 뭘 순서대로
할지"** 는 못 다룬다. 반대로 TODO 앱은 순서는 있지만 시간 감각이 없다.

이 위젯은 그 사이를 메운다.

- 하루의 **앵커**(시작 기준 시각)를 정하면, 로컬 일정은 그 시각부터 소요시간만큼 **줄줄이
  이어 붙는다**. 앞의 일이 길어지면 뒤가 통째로 밀린다.
- 구글 캘린더 일정은 **고정 장애물**이다. 큐가 알아서 비켜 간다.
- 시각이 정해진 일은 TODO 슬롯으로 절대 시각에 박아둔다.

## 주요 기능

| | |
|---|---|
| **앵커 기반 큐** | "저녁 8시부터 밥 1시간, 과제 2시간" 식으로 순서만 정하면 시각은 알아서 계산된다 |
| **자동 밀림** | 앞 항목의 길이를 바꾸면 뒤가 따라 움직인다. 하루를 넘기면 다음 날로 이월 |
| **Google Calendar 양방향** | 5분마다 동기화. 홀드 후 드래그하거나 상세에서 고치면 구글에 반영된다 |
| **자연어 명령** | ✨ 버튼 → "내일 저녁 8시에 캡스톤 미팅 1시간" 한 줄이면 끝 |
| **미배치 TODO** | 시간을 안 정한 일은 아래 목록에 쌓아두고, 그리드로 끌어다 놓으면 배치된다 |
| **마감 카운트다운** | 임박도에 따라 색이 바뀐다 |
| **완료 기록** | 날짜별로 접었다 펴는 히스토리. 카테고리별로 기록에서 뺄 수도 있다 |
| **상주 위젯** | 항상 위, 반투명 유리, 이동/고정 모드, 클릭 통과, 부팅 시 자동 실행 |

TODO는 **시간이 지나도 자동으로 완료되지 않는다.** 안 한 일이 조용히 "완료"로 둔갑하면
다음 날 기록을 훑어봐도 착각을 걸러낼 수 없기 때문이다. 지난 항목은 흐리게 + "지남" 뱃지만 붙는다.

## 설치

### 설치본으로

[Releases](../../releases)에서 `weektodo-widget-*-setup.exe`를 받아 실행한다.
코드 서명을 하지 않아 SmartScreen 경고가 뜨는데, **추가 정보 → 실행**으로 넘기면 된다.

### 소스에서 빌드

```bash
git clone <이 저장소>
cd WeekToDo
npm install          # postinstall이 better-sqlite3를 Electron ABI로 빌드한다
npm run dev          # 개발 실행
npm run dist         # dist/weektodo-widget-*-setup.exe
```

Node 20+ 와 Windows 빌드 도구가 필요하다 (`better-sqlite3`가 네이티브 모듈이다).

## 처음 설정

데이터·자격증명은 **전부 이 PC에만** 있다. 서버도 계정도 없다.

```
%APPDATA%/weektodo-widget/
  app.db            일정·TODO·설정 (SQLite)
  google-auth.json  구글 토큰      (safeStorage 암호화)
  llm-auth.json     Anthropic 키   (safeStorage 암호화)
```

### Google Calendar 연동 (선택)

공용 클라이언트를 심어두지 않았으므로 **각자 발급받아야 한다.**

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고
   **Google Calendar API**를 켠다.
2. `사용자 인증 정보 → OAuth 클라이언트 ID → 데스크톱 앱`으로 클라이언트를 만든다.
3. 위젯의 `설정 > 구글 캘린더`에 클라이언트 ID와 시크릿을 넣는다.
   (암호화되어 이 PC에만 저장되고 화면에 다시 표시되지 않는다)
4. **구글 계정 연결** → 브라우저에서 로그인 → 동기화할 캘린더를 고른다.

받는 권한은 두 개뿐이다: 이벤트 읽기·쓰기(`calendar.events`)와 캘린더 목록 읽기.

### 자연어 명령 (선택)

`설정 > 명령 입력`에 [Anthropic API 키](https://console.anthropic.com/)를 넣는다.
기본 모델은 **Haiku 4.5** — 하는 일이 "한 줄 → 도구 호출"이라 추론이 거의 없고,
치고 바로 닫는 흐름이라 속도가 곧 쓸모다. 요금은 각자의 Anthropic 계정으로 청구된다.

명령 창은 **대화가 아니다.** 답변 말풍선도 결과 로그도 없고, 피드백은 위젯이 실제로
바뀌는 것으로 준다. 애매해도 되묻지 않고 가장 그럴듯한 해석으로 바로 실행한다.

```
내일 저녁 8시에 캡스톤 미팅 1시간
오늘 앵커 8시로
7~8시 밥, 8~10 과제, 10~11 게임
```

일정을 만들고 고칠 수는 있지만 **지우지는 못한다.** 되돌릴 수 없는 조작을 모델 판단에
맡기지 않는다 — 삭제는 그리드에서 우클릭으로 직접 한다.

## 쓰는 법

- **앵커** — 날짜 머리의 ⚓ 를 눌러 그날의 시작 시각을 정한다. `▶ 지금`은 현재 시각으로,
  요일별 기본값은 설정에서. 부팅 시 자동 실행되면 그 시각이 30분 단위로 올림돼 자동 기록된다.
- **일정 추가** — 날짜 머리의 `+`. `밥 60`처럼 뒤에 숫자를 붙이면 소요시간(분)이 된다.
- **홀드** — 로컬·구글 일정은 자물쇠를 풀어야 끌어 옮길 수 있다. 실수로 남의 캘린더를
  건드리지 않기 위해서다.
- **우클릭** — 빈 칸에서는 TODO/일정/구글 일정 만들기, 블록 위에서는 편집·삭제.
- **모드** — 🔒 이동/고정, ⤢ 오늘+내일 ↔ 7일.

## 설계 원칙

이 프로젝트가 지키는 규칙 몇 가지. 자세한 것은 [CLAUDE.md](CLAUDE.md)와
[docs/PLAN.md](docs/PLAN.md)에 있다.

1. **파생 시각은 저장하지 않는다.** `local_events`는 소요시간과 순서만 갖는다.
   시작·종료 시각은 그릴 때마다 `앵커 + 앞 항목들의 누적`으로 계산한다.
2. **스케줄 계산은 순수 함수로 격리한다.** `src/shared/scheduler/`는 DB·IPC·React를
   import하지 않는다. 이 레이어는 UI보다 먼저 테스트로 고정했다.
3. **구글 이벤트는 고정 장애물이다.** 자동 판단(밀림·이월·자연어 명령)은 절대 구글을
   건드리지 않는다. 사용자가 직접 하는 것만 예외다.
4. **TODO는 자동 완료되지 않는다.**
5. **날짜는 항상 논리적 날짜.** `dayStartHour`(기본 6시) 기준이라 새벽 3시는 "어제"다.
6. **데이터는 삭제하지 않는다.** 완료된 TODO도 보존한다.

## 기술 스택

| 영역 | 선택 |
|---|---|
| 셸 | Electron 43 (프레임리스 + Windows 11 acrylic + always-on-top) |
| 빌드 | `electron-vite` (main / preload / renderer 3-타깃) |
| UI | React 19 + TypeScript |
| DB | `better-sqlite3` — **메인 프로세스 전용** |
| 구글 | `@googleapis/calendar` + `google-auth-library` |
| 자연어 | Anthropic Messages API를 `fetch`로 직접 |
| 테스트 | `vitest` — 스케줄 계산 엔진 위주 (123개) |

```
src/
  main/       Electron 메인 — DB, 구글 동기화, 자연어 명령, 창 관리
  preload/    contextBridge로 노출하는 IPC 통로
  renderer/   React UI
  shared/     순수 계산 엔진 · IPC 계약 · 타입 (main/renderer 공용)
```

렌더러는 `fs`·`better-sqlite3`·`googleapis`를 직접 부르지 않는다. 전부 preload가 노출한
IPC를 통한다.

## 개발

| 명령 | 용도 |
|---|---|
| `npm run dev` | 개발 실행 (HMR) |
| `npm run build` | main/preload/renderer 번들 빌드 |
| `npm test` | vitest |
| `npm run typecheck` | node/web 두 tsconfig 모두 검사 |
| `npm run rebuild` | 네이티브 모듈을 Electron ABI로 재빌드 |
| `npm run dist` | Windows 설치본 빌드 |

개발 실행과 설치본은 **같은 데이터 폴더**를 쓴다. 둘을 동시에 띄우면 단일 인스턴스 락
때문에 나중 것이 앞의 창만 띄우고 끝난다.

VS Code에서 개발한다면 `.vscode/settings.json`이 필요하다 — 확장 호스트가 자식 프로세스에
`ELECTRON_RUN_AS_NODE=1`을 물려주는데, 그대로 두면 Electron이 평범한 Node로 실행되어
`require('electron')`이 API 객체 대신 경로 문자열을 돌려주고 죽는다.

## 알려진 제약

- **Windows 전용.** 유리 배경(`backgroundMaterial: 'acrylic'`)과 시작프로그램 등록이
  Windows에 묶여 있다.
- **유리 배경은 비활성 창에서 흐림이 꺼진다.** Windows 11의 의도된 동작이라 Electron
  옵션으로 못 바꾼다.
- **코드 서명·자동 업데이트 없음.** 새 버전은 다시 설치하면 되고, 데이터는 그대로 남는다.
- 알림, 모바일/클라우드 동기화, 손으로 만든 TODO의 카테고리 자동 분류는 범위 밖이다.
